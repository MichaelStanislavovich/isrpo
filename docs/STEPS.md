# Этапы разработки TODO Navigator

## 1. Выбор функциональности

Задача: собрать комментарии `// TODO [high]: ...` и `// FIXME [low]: ...` в боковом дереве VS Code. В версии 0.2 поддерживаются C++ и JS/TS, но используется простой формат комментариев, чтобы можно было объяснить каждую строку кода.

## 2. Настройка `package.json`

`main` указывает на `src/extension.js`. `viewsContainers.activitybar` создаёт иконку в левой панели. `views` регистрирует представление `todoNavigator.tasks`. `contributes.commands` объявляет команды для палитры, а `menus.view/title` добавляет кнопки над списком.

## 3. Парсер `src/parser.js`

Каждый файл разбивается на строки по `\n` или `\r\n`. Регулярное выражение проверяет соответствие формату. Три группы — тип, приоритет, текст. Объект задачи содержит также номер строки (с нуля). `filterTasks` позволяет независимо ограничить тип и приоритет.

## 4. Сканер `src/scanner.js`

`workspace.findFiles` находит JS/TS-файлы по маске, исключая служебные папки. `workspace.fs.readFile` читает байты файла, из которых формируется текст UTF-8. `parseTasks` возвращает задачи, к каждой добавляется ссылка `uri` на файл.

## 5. Дерево `src/tree.js`

`TaskTreeProvider` реализует `getChildren()` и `getTreeItem()`. На верхнем уровне элементы-файлы, под ними — комментарии. `EventEmitter` уведомляет редактор об изменении данных. По клику выполняется зарегистрированная команда открытия задачи.

## 6. Связка в `src/extension.js`

`activate` создаёт представление, регистрирует команды обновления, фильтров и перехода. `onDidSaveTextDocument` вызывает новый поиск после сохранения JS/TS-файла. `context.subscriptions` содержит освобождаемые ресурсы.

## 7. Проверка

Выполняем `npm test` и `npm run check`. Затем открываем проект в VS Code, нажимаем F5, проверяем дерево, переход, фильтры и реакцию на сохранение. Скриншоты интерфейса делаем **в реальном Extension Development Host**, а не из макета.

## 8. Размещение на GitHub

Создаём публичный репозиторий, добавляем файлы без `node_modules`, делаем коммит и push. В `README.md` уже есть ФИО, группа, название и возможности. После публикации нужно вставить действительную ссылку на репозиторий.
